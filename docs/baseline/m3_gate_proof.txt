# M3 gate proof — cold DMA ring allocation
# Captured 2026-05-24 in rtl8125-guest (custom debug+Rust kernel 7.0.0 #2).
# Satisfies plan §7 M3 acceptance.

## What this proves

`r8125_rust` (M3 deliverable) satisfies plan §7 M3 on every point:

1. **TX + RX descriptor structures** — `src/ring.rs::Descriptor` is
   `#[repr(C)]` with `u32 opts1`, `u32 opts2`, `u64 addr` (mirroring r8169's
   `struct TxDesc`/`struct RxDesc`). Size 16 bytes, align 8, both asserted
   at compile time via `const _: () = assert!(...)`.
2. **Coherent DMA allocation** — `Ring<N>::new` calls
   `kernel::dma::CoherentAllocation::alloc_coherent` for `N + 1`
   descriptors (the `+1` is the tail canary slot). Drop on the
   `CoherentAllocation` calls `dma_free_coherent`.
3. **Streaming-mapping plan documented** — `src/dma.rs` module docs spell
   out the RX-refill / TX-completion ownership state machine for M4 in
   terms of `kernel::dma`'s `DataDirection::FromDevice` /
   `DataDirection::ToDevice` mappings, the §6.3 contract, and the parallel
   software-shadow slot.
4. **Typed ring indices** — `TxHead`, `TxTail`, `RxHead`, `RxTail` are
   distinct newtype wrappers over `usize`; the compiler refuses to
   substitute one for another.
5. **Compile-time bounds** — `const RING_LEN: usize = 256` (matches r8169
   `NUM_TX_DESC` / `NUM_RX_DESC`); `Ring<{ RING_LEN }>` carries the count
   in the type. `assert!(RING_LEN.is_power_of_two())` makes the wrap-mask
   in `*Head`/`*Tail::wrapped()` a compile-time `& (N - 1)`.
6. **`CONFIG_DMA_API_DEBUG` enabled** — already on in this guest's debug
   build (`CONFIG_DMA_API_DEBUG=y`); the 1000-cycle gate log below shows
   zero `dma_debug` warnings.
7. **Descriptor canaries** — two layers:
   - **Shadow canaries**: a per-descriptor `[u64; N]` in `Ring`'s
     CPU-resident memory, seeded with `0xDEAD_BEEF_CAFE_BABE`. Catches a
     driver-side stray write in M4+.
   - **Tail canary**: descriptor slot `N` of the DMA-coherent ring (one
     past the last hardware-visible slot), seeded with
     `opts1=0xDEAD_BEEF`, `opts2=0xCAFE_BABE`, `addr=0xFEED_FACE_BAAD_F00D`.
     Catches a device-side one-off-the-end DMA write in M4+.
   `Ring::verify_canaries()` checks both layers and is called at the end of
   probe (in M3 it is vacuously true; the infrastructure lights up in M4).

`src/unsafe_boundary.rs` gains its first three real residents at M3, each
with a §6.2 `SAFETY:` comment:
- `set_64bit_dma_mask(pdev)` — wraps the kernel-Rust
  `unsafe fn dma_set_mask_and_coherent`.
- `unsafe impl AsBytes for ring::Descriptor` — proves plain-old-data.
- `unsafe impl FromBytes for ring::Descriptor` — same.

CI `ci/.unsafe-census` re-baseline 0 → 3 documented inline (the first
intentional bump since M0a) — every other crate file still carries
`#![deny(unsafe_code)]`.
