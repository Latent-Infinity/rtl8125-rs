# Phase 6 — Guest serial-console capture + deliberate panic test
# Captured 2026-05-22 on ms-a2-controller. Clears M1 tracker row 13.
# Proves a guest kernel panic is recoverable as text on the host BEFORE the
# guest is trusted with driver code (runbook Phase 6 / plan §15 #13).

## Setup
guest        : rtl8125-guest (custom debug+Rust kernel 7.0.0 #2)
serial path  : guest cmdline has console=ttyS0,115200n8 -> kernel/panic output
               goes to the emulated ISA serial port.
host capture : two independent host-side sinks were configured —
  1. libvirt <log> element on the <serial> device, written by virtlogd:
       <serial type='pty'>
         <log file='/var/log/libvirt/qemu/rtl8125-guest-serial.log' append='off'/>
       VM XML patched + redefined via `virsh define` this session.
  2. live `virsh console rtl8125-guest` capture (the excerpt below), run under
     a script(1)-allocated pty so virsh has a controlling TTY.

## Trigger (inside the guest — this DELIBERATELY crashes the guest)
  echo 1 > /proc/sys/kernel/sysrq
  sync
  echo c > /proc/sysrq-trigger          # sysrq_handle_crash -> NULL deref panic
