# M4-skeleton proof — net_device + cshim wired; no peer yet
# Captured 2026-05-24 in rtl8125-guest (custom debug+Rust kernel 7.0.0 #2).
# This is the no-peer subset of plan §7 M4; the peer-dependent items
# (ping / iperf3 / on-wire capture) wait for the M0b peer.

## What this proves (no peer required)

The M4 architecture is in place: the C shim (`src/netdev_bridge.c` /
`src/netdev_bridge.h`) implements the §6.3 contract; the Rust crate
allocates + registers a `net_device` via the shim and tears it down on
unbind. The composite Rust+C module builds cleanly and survives a
1,000-cycle insmod/rmmod regression with zero leaks, warnings, or
KASAN/lockdep/DMA_API_DEBUG complaints — i.e., the lifetime handling
across the FFI is sound under the debug instrumentation.

What we have NOT verified (and explicitly defer to the peer-ready phase):

- packets actually move (TX queue stays stopped; carrier stays off);
- ARP / ping / DHCP / iperf3;
- IRQ handler + NAPI poll bodies (the cshim wires them; the Rust
  callbacks are stubs returning 0 work);
- §6.3 type-state ownership transitions exercised by real traffic
  (`src/skb.rs` / `src/napi.rs` are still empty — the contract in
  `netdev_bridge.h` and the C-side counters are in place, waiting).

## Architecture in place

### C shim — `src/netdev_bridge.{c,h}`

- 346 LOC of C (under the plan's ≤400 LOC cap).
- Implements the canonical §6.3 sk_buff ownership contract:
  - TX path: `bridge_skb_dma_map_tx` (counter `tx_received++`),
    `bridge_skb_complete_tx` (counter `tx_consumed++`),
    `bridge_skb_free_error` (counter `tx_dropped_error++`).
  - RX path: `bridge_skb_build_rx`, `bridge_skb_deliver_rx`
    (counter `rx_handed_to_stack++`), `bridge_skb_drop_rx`
    (counter `rx_dropped_error++`).
  - Counter snapshot via `bridge_counters_snapshot` — wired but not yet
    consulted by Rust (M4-full will check the §6.3 invariant
    `tx_received == tx_consumed + tx_busy_exception + tx_dropped_error`
    in a CI smoke test).
- Vtable (`struct r8125_bridge_ops`) holds Rust `extern "C" fn` pointers
  for `open`/`stop`/`xmit`/`poll`/`change_mtu`.
- NAPI registration in alloc; `bridge_napi_schedule`/`napi_complete_done`
  helpers exposed for the IRQ + poll wire-up that comes with peer testing.

### Rust shim glue

- **`src/netdev.rs`** — `BridgeOps` vtable (`M4_SKELETON_OPS`) +
  RAII handle `NetdevHandle` whose Drop calls the cshim's
  `r8125_bridge_unregister_and_free`. Vtable callbacks are stubs that
  reject TX defensively (`dev_kfree_skb_any` + `NETDEV_TX_OK`), return
  0-work from poll, and no-op for open/stop/change_mtu.
- **`src/unsafe_boundary.rs`** — extern decls for the cshim functions,
  safe wrappers each with a §6.2 SAFETY comment, plus the cast that
  extracts the raw `*mut pci_dev` from `&pci::Device` (the kernel Rust
  API doesn't expose this publicly; we ride the `Opaque<T>::get()`
  documented escape hatch + `#[repr(transparent)]` layout).
- **`src/pci.rs`** — probe now also calls
  `NetdevHandle::new(pdev)?` and stores the handle in `R8125Driver`;
  drop order is `_netdev → rx_ring → tx_ring → _bar → pdev`, so the
  netdev unregisters before any DMA frees or BAR unmaps.

### Build / kbuild

- `src/Kbuild` is now a composite-module recipe:
  `obj-m += r8125_rust.o; r8125_rust-y := r8125_rust_main.o netdev_bridge.o`.
- Rust crate root renamed `r8125_rust.rs → r8125_rust_main.rs`.
  Same name as the composite module triggers a kbuild circular-dep
  warning and silently drops the Rust .o (the trap that turned the
  first M4 build into a C-only 700 KB .ko). Matches
  `samples/rust/rust_print` exactly: `rust_print_main.rs` +
  `rust_print_events.c` → `rust_print.ko`.
- Final `r8125_rust.ko`: 1 633 888 bytes (Rust + C + KASAN).

## What remains for M4-full (peer-driven)

1. Read the device's real MAC from MMIO `IDR0..IDR5` (offsets 0x00..0x05)
   instead of the locally-administered placeholder
   `02:00:00:00:00:01` — single `bar.read32`/`read16` call pair.
2. Wire IRQ via `pci::Device::request_irq` with a `kernel::irq::Handler`
   that calls `r8125_bridge_napi_schedule`.
3. ndo_open: program TX/RX ring DMA addresses into `TNPDS`/`RDSAR`
   registers, post initial RX buffers, enable hardware TX/RX,
   `napi_enable`, `netif_carrier_on`, `netif_start_queue`.
4. ndo_stop: reverse — `netif_tx_disable`, `napi_disable`, disable
   hardware TX/RX, reap pending TX, free posted RX buffers.
5. `src/skb.rs` — type-state `TxSkb<S>` per plan §6.3.
6. `src/napi.rs` — RX-completion + TX-completion loop.
7. ndo_start_xmit: validate, `bridge_skb_dma_map_tx`, find free TX
   slot, write descriptor, `kick` device. Return BUSY only when
   ring-full race lost (counted exception per §6.3).
8. `ip link set up`/`down` 100-cycle test, ARP/ping/DHCP, iperf3 baseline.
9. CI smoke test asserting `tx_received == tx_consumed + tx_busy +
   tx_dropped` (§6.3 invariant) at quiesce.

All eight items require traffic to a peer; none are blocked by code I
could write without one.
