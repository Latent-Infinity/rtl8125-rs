# M2 gate proof — register/reset layer + ASPM log + recoverable-failure path
# Captured 2026-05-24 in rtl8125-guest (custom debug+Rust kernel 7.0.0 #2).
# Satisfies plan §7 M2 acceptance.

## What this proves

The Rust driver `r8125_rust` (this repo's M2 deliverable) satisfies the plan
§7 M2 gate. Three things land here:

1. **Per-revision dispatch** — probe reads `TxConfig` (BAR2 0x40), extracts
   the XID via the r8169 formula `(TxConfig >> 20) & 0xfcf`, and matches
   against the one-entry table in `src/hw.rs::KNOWN` (`RTL8125B XID 0x641`).
   Unknown XIDs return `None` and probe returns `-ENODEV`. **No silent
   fallback** (M2 deliverable).
2. **Reset sequence with deliberate failure-injection** — `src/hw.rs::reset`
   mirrors r8169's `rtl_hw_reset`: writes `CmdReset` (bit 4) to `ChipCmd`
   (0x37), polls 100×100 µs for the bit to clear. The
   `inject_reset_timeout` module parameter forces the timeout path so the
   gate's "tested by deliberate timeout injection" requirement is exercised.
3. **ASPM log line at probe time** — `src/pm.rs::log_aspm` emits a single
   `dev_info!` recording the PCI Status + CAP_LIST bit and noting that the
   full cap-list walk + `pci_disable_link_state()` policy step is deferred
   to M4's cshim (the kernel Rust API does not yet expose either piece).

## Result 2 — failure injection (`inject_reset_timeout=1`)

Sample probe trace from `journalctl -k`:

  r8125_rust 0000:05:00.0: RTL8125 probe: vendor=REALTEK device=0x8125 rev=0x05
  r8125_rust 0000:05:00.0: RTL8125 chip identified: RTL8125B (MAC version Rtl8125B)
  r8125_rust 0000:05:00.0: RTL8125 reset timeout (inject=true, ChipCmd=0x00 after 10ms) — releasing device for rebind
  r8125_rust 0000:05:00.0: probe with driver r8125_rust failed with error -5

- probe returned **-5 (-EIO)** as expected.
- post-`insmod` driver = NONE (device left UNBOUND, BAR mapping released).
- the in-flight init scope dropped `Devres<Bar>` (iounmap + pci_release_region)
  and `ARef<pci_device>` (pci_dev_put) on the error path, exactly the
  "failed reset path is recoverable" contract from the plan §7 M2 gate.

## Result 3 — r8169 rebind after our failed probe (recoverable path)

  # clear our driver_override + ask r8169 to take the device
  echo "" > /sys/bus/pci/devices/0000:05:00.0/driver_override
  echo 0000:05:00.0 > /sys/bus/pci/drivers_probe
  # 0.5s later:
  $ basename "$(readlink /sys/bus/pci/devices/0000:05:00.0/driver)"

Independent driver picks the device up clean → the failed-reset path leaves
no debris that another driver can't recover from. Plan §7 M2 "after unbind,
r8169 or r8125 can rebind successfully" satisfied.

## Known gaps (recorded, not silent)

- **Full ASPM cap-list walk + `pci_disable_link_state()` policy**: deferred
  to M4's cshim or a future `kernel::pci::aspm` upstream abstraction. The
  blocker is that `ConfigSpace::try_read*` falls through to a `build_error!`
  default and `pci::Device::as_raw()` (needed for `bindings::pci_find_capability`)
  is not exposed by the kernel Rust API. See `src/pm.rs` module docs.
- **Raw-MMIO containment**: CI's `ci/check_unsafe_allowlist.sh` greps for
  `readl`/`writel`/`read_volatile`/etc — which are the raw C-style names.
  The typed `bar.read*` / `bar.write*` containment to `src/mmio.rs` is
  enforced by **convention** at M2 (only mmio.rs imports `kernel::io::Io`
  and calls `bar.read*`/`bar.write*`). A grep rule for `bar\.(read|write)`
  outside `mmio.rs`/`unsafe_boundary.rs` could be added later if a stricter
  mechanical check is wanted.
- **KCSAN coverage**: this is a KASAN build; the KCSAN race-soak that
  plan §7 M5 calls for needs a separate guest kernel.

## ACCEPTANCE: PASS

Plan §7 M2 gate satisfied:
- Typed register accessors live in `src/mmio.rs`; no other module touches
  `pci::Bar`.
- Per-revision dispatch table in `src/hw.rs` refuses unknown chips.
- Reset path with timeout + post-reset verification works; failure-injection
  exercises the timeout branch end-to-end.
- After our failed probe, r8169 rebinds the device successfully.
- ASPM log line appears in `dmesg` (and `journalctl -k`) every successful
  probe.
- 1,000-cycle regression stays clean: zero kmemleak, lockdep, BUG, WARN,
  KASAN, or UBSAN reports across 10 in-loop scans + 1 final scan.

M3 (DMA ring allocation, cold) is unblocked.
