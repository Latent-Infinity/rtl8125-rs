RUNTIME-PM MODEL (W2.4)
-----------------------
Closed-interface autosuspend, deadlock-safe by construction:
- runtime_idle vetoes (-EBUSY) whenever netif_running -> the device only ever
  autosuspends while the interface is administratively DOWN, so the
  suspend/resume callbacks never touch rings/RTNL (the close already quiesced
  the HW; the PCI core does the D-state).
- The ndo open/stop pm_runtime get/put_sync brackets live in dedicated *_entry
  wrappers (registered in netdev_ops), NOT in bridge_ndo_open/stop — those are
  reused by the PM/reset/AER resume paths where pm_runtime_get_sync would
  deadlock. Brackets are gated on a runtime_pm flag set only on a RUNTIME_PM=1
  build, so the default build is byte-identical.
- Autosuspend is gated on pci_dev_run_wake (mirrors r8169): only a device that
  can wake from D3 is allowed to autosuspend.

AER × RUNTIME-PM LOCKDEP ABBA — found + fixed
---------------------------------------------
The COMBINED AER=1+RUNTIME_PM=1 build tripped a lockdep circular dependency
(individual AER-only and RUNTIME_PM-only builds were each clean):
  edge A: ndo_open/stop hold rtnl -> pm_runtime get/put_sync -> D-state ->
          pcie_aspm_pm_state_change -> down_read(pci_bus_sem)   [rtnl -> pci_bus_sem]
  edge B: AER core runs error_detected/resume under pci_walk_bus's pci_bus_sem,
          and our callbacks took rtnl                            [pci_bus_sem -> rtnl]
  => ABBA. Both D0-resume and low-power paths in pci.c take pci_bus_sem, so
     edge A cannot be removed from the runtime-PM side.

FIX: make the AER callbacks RTNL-FREE (the igb io_error_detected model), removing
edge B entirely:
- error_detected: a non-fatal (Normal) channel does NOTHING (returns CanRecover;
  the device still works / was already re-init'd by reset_done). Only
  Frozen/unknown channels take the full-stop RTNL-free
  r8125_bridge_pm_error_detach path; permanent failure is detach-only because the
  core returns Disconnect and may not call resume.
- resume: new RTNL-free r8125_bridge_pm_error_resume (was reusing the rtnl-taking
  bridge_pm_resume); re-opens only what the teardown tore down (b->aer_torn_down).
- reset_prepare/reset_done keep rtnl: they run under device_lock (pci_reset_*),
  not pci_bus_sem, so no cycle there.
CI gate ci/check_aer.sh statically enforces both AER callbacks are rtnl_lock-free.
