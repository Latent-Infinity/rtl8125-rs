PCIe AER recovery (error_detected / slot_reset / resume) — live validation
==========================================================================

Driver build : make PCI_PM=1 SHUTDOWN=1 RESET=1 AER=1   (cfg r8125_pci_aer)
Kernel       : 7.0.0-kasan, rust/kernel/pci.rs carrying patches 0001-0004
DUT          : gateway 0000:03:00.0 (RTL8125B, MAC_VER_63), enp3s0 @ dut netns
Trigger      : echo 1 > /sys/bus/pci/devices/0000:03:00.0/reset
               (this controller's only reset_method is "bus" = secondary-bus
                reset; the chip answers every bus reset with an Uncorrectable
                non-fatal AER, UnsupReq — which is what exercises the AER path)

WHY THIS IS NEEDED
------------------
Before patch 0004 the same reset logged:
    pcieport 0000:00:03.1: AER: can't recover (no error_detected callback)
i.e. the err_handler was registered (0003) but the AER core bailed for lack of
error_detected. W2.3 adds the three recovery callbacks so the recovery completes.

VERDICT POLICY (src/aer.rs, host-tested)
----------------------------------------
The first cut returned NEED_RESET for the non-fatal channel (the igc pattern).
On THIS device that looped forever: NEED_RESET -> AER core does a slot reset ->
slot reset is a secondary-bus reset -> chip emits another UnsupReq -> AER fires
again -> ... a reset storm (one new Uncorrectable error every ~3s, indefinitely).
Fix = the igb pattern: a non-fatal (pci_channel_io_normal) channel returns
CAN_RECOVER (recover in place, no extra reset); only a fatal/frozen channel
returns NEED_RESET. The core still calls resume on the CAN_RECOVER path
(drivers/pci/pcie/err.c: CAN_RECOVER -> RECOVERED -> report_resume), so the
device is rebuilt either way. The original validation build tore down and
reopened on the Normal path too; the current lockdep-fixed implementation keeps
Normal untouched because reset_done has already rebuilt it, and only
Frozen/unknown channels use the balanced full-stop/resume pair. Permanent failure
is detach-only because the AER core returns Disconnect and may not call resume.

REVISION 2026-06-18 — AER callbacks made RTNL-FREE (lockdep fix)
---------------------------------------------------------------
After the combined AER+RUNTIME_PM build exposed a lockdep ABBA (rtnl <-> pci_bus_sem;
see docs/perf/feature_smoke/runtime_pm.txt), error_detected/resume were revised to
the igb rtnl-free model: a non-fatal (Normal) channel now does NOTHING in
error_detected (returns CanRecover; the device keeps working / was re-init'd by
reset_done) instead of the earlier detach+stop+reopen. Frozen/unknown channels
take the RTNL-free full-stop r8125_bridge_pm_error_detach path and resume uses
the new RTNL-free r8125_bridge_pm_error_resume (gated on b->aer_torn_down).
Permanent failure is detach-only so a later unregister cannot double-disable NAPI
after a Disconnect result. The verdict policy (Normal->CanRecover,
Frozen->NeedReset, PermFailure->Disconnect) is unchanged, so the validated
recovery outcome above still holds; the device now re-inits ONCE (via reset_done)
on the echo-1>reset path instead of twice.
